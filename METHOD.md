# Maintain a capability

A capability declares its purpose, accountable owner, authoritative inputs, method or engine, consumer, trigger, allowed effects, output check, failure route and stop condition. Reuse an existing canonical contract whenever it already carries those facts. Derived views link to the contract.

## One improvement cycle

Observe a real failure or unnecessary cost. Freeze the acceptance criteria and compare against an unchanged baseline. Propose the smallest correction. Evaluate it in an isolated or reversible scope. An authorized writer checks permissions and current preconditions, preserves recovery and applies it. Inspect the resulting state and exercise the actual consumer. Retain failed attempts as attempts, not outcomes.

Turn the observed failure into a reusable check or specific method correction. Test another case that was not supplied to the repairer as an expected answer. A stored lesson is captured learning; a changed artifact is implementation; successful use on another case is bounded transfer evidence. Do not generalize one pilot to unrelated domains.

## Keep direction stable

Human owners determine ends and constraints. Candidate authors cannot redefine success, permission policy or budgets. Use independent state checks for observable facts, calibrated judgment for quality, and human decisions for values and commitments. Every improvement must justify its operating and maintenance cost. Prefer simplification when quality is unchanged.

Use explicit candidate/accepted versions, current preimages, stable work identity, bounded retries and recovery. Distinguish absent events from failed collection. Stop when the authorized result passes; expand only under a new scoped mandate. The method may itself be improved with independent evaluation; self-improvement does not grant self-authorization.

## Reusable route-repair pattern

An existing catalog can still be undiscoverable. Check both that it exists and that a consumer entry explicitly routes to it. Validate the declared file chain and collection shape, then have a fresh consumer find and use it without supplying its destination. Preserve the distinction between a recorded capability and an observed runtime.

The route sensor only emits observations. It never edits maps, registries, policies or schedules. It does not parse arbitrary prose into autonomous repair authority. Its regression cases cover broken links, invalid sources and root escape; a fresh consumer remains a separate acceptance step.

## Public and private evolution

The public method uses synthetic fixtures and portable contracts. A private instance owns its evidence and configuration. Export only explicitly reviewed neutral corrections; test imports against the instance's private constraints before adoption. A private repository is not a credential vault, and local storage is not a guarantee about inference transmission.

Runtime enforcement must cover every write route available to a candidate. Prompt instructions or a tool-specific guard alone do not constitute adversarial isolation. When that boundary is unavailable, keep modification supervised and report the limitation.
